# Full audit, weeks 0–12 (14 Oct 2026, D-50)

Six independent reviews, every line in scope, each finding reproduced (scratch scripts, throwaway brokers, a
scratch vitest harness, mutation runs) or shown by exact code path. Decision per finding: **fix**, **defer**
(open issue, reason), or **accept** (reason). IDs are used in commits, tests and PROGRESS.

Areas: **I** infrastructure, broker, DevOps · **W** backend web layer · **D** backend data and logic ·
**F** frontend and nginx · **C/T** runner, import, examples, test quality · **S** simulator.

## I · Infrastructure, broker, DevOps

| ID | Sev | Finding | Decision |
|---|---|---|---|
| I1 | High | Broker memory DoS: retained messages, queues and connections unbounded; `uagv/+/` in the ACL lets one robot or master login create any number of retained topics (3 MiB → 104 MiB in 400 publishes) | **Fix**: `memory_limit`, `max_queued_messages`, `max_queued_bytes`, `max_inflight_messages`, `max_connections`; ACL version level explicit (`v1`, `v2`, `v3`); container memory limit |

## A · Architecture (system view across all reviews)

**What holds up.** Clear trust boundaries on paper: MQTT clients (robots, fleet managers) and uploaded files are
untrusted; browsers are trusted after login. Least-privilege broker logins per robot and per master (D-23,
D-28, D-47). No database: sessions are append-only JSONL files with server-chosen names, which made the file
handling review clean. The scenario runner is a black-box client of the public API (D-45), so it tests what
users get. Frontend and backend are tied by shared contract fixtures (D-38), which several reviews relied on.

**What the reviews have in common.** Most High findings are one pattern: *untrusted content crosses a boundary
and is trusted on the other side*. Numbers that overflow (W1, D1), topics with control characters (D4), wrong
kinds of values in robot state (F1, F2), malformed order graphs (S3), floods (I1, S1). Each layer validated
its own inputs well against the attacks it was designed for, and less well against inputs that were valid
at the layer before. Fix rule adopted for all areas: **every component validates at its own boundary,
whatever the previous one did** (the simulator does not rely on the backend's validator, the UI does not rely
on the backend's parser, the backend does not rely on the broker).

| # | Observation | Recommendation | When |
|---|---|---|---|
| A1 | One shared simulator thread for all robots: one hostile input stalls every robot (S1, S2) | Per-robot work budgets (S1 fix); process isolation only if user labs need hundreds of robots | Done in S1 |
| A2 | One backend process, one MQTT connection, in-memory hub: the backend is the single point of failure; anything that disconnects it (D4) blinds the lab | Validate before publishing (D4), check publish results (D14), restart policy (I2); a health metric for the MQTT link | Done in D4/D14/I2; metrics below |

## Result (gate, 14–15 Oct 2026)

All findings marked **Fix** are fixed, each with a test that fails on the old code, except the cosmetic merge of
the two session-id generators (open) and the simulator's now-unreachable edge-action code (cleanup, open).

| Check | Before | After |
|---|---|---|
| Backend tests | 463 | 576 |
| Simulator tests | 397 | 465 |
| Runner tests | 148 | 220 (13 surviving mutations now caught) |
| Frontend tests | 99 | 137 |
| e2e (45 tests) | — | 41 + 4 login-only skipped on VDA 2.1 and on 3.0; 44 + 1 on 2.1 with login and TLS |
| Load test, 10 / 25 / 50 robots | 18/18 | all thresholds met, browser included (54 fps, 10.7 MiB heap at 50 robots) |
| Black-box attacks (19) | 14 refused, 2 real header findings | 16 refused; the remaining 3 are verified non-issues |
| Reproduction scripts | each finding reproduced | each re-run: refused, bounded or correct (e.g. replay burst stall 6.9 s → 0.03 s; broker flood capped at the memory limit) |

Found by the gate itself: the load test's browser probe was blocked by the new CSP (`unsafe-eval`): the
measuring tool now bypasses the CSP (the e2e browser tests keep the real policy); a missing asset's 404 was
marked cacheable for a year: cache header only on success.

## Review method

Each area by a separate reviewer with its own context: security auditors for the backend and infrastructure,
code reviewers for the frontend and simulator, a test engineer for the runner and the suites. The fixes are
built per area by workers from this file, each owning a disjoint set of files, then reviewed, merged and run
through the full gate (all suites, e2e in three configurations, CI) here.
